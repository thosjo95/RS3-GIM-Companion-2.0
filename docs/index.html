RS3 GIM Companion 2.0

The Group Ironman tracker that reads the game itself.

In development RuneScape 3 Lua plugin MIT licence

What is GIM 2.0?

GIM Companion 1.x tracks your Group Ironman team from the public RuneScape hiscores and Adventurer's Log. GIM 2.0 adds a plugin that runs inside the RuneScape 3 client and sends the things the web APIs cannot give you: what is in the bank and the shared group storage, live quest progress, lifetime boss kills, area tasks and achievements, the Group Ironman Journey, drops and more. The dashboard keeps its look and all of its 1.x features, and the new live data feeds them.

Status: GIM 2.0 is under development and has not been released. The live site at groupiron.com still runs the 1.x line. The plugin works in the RuneScape beta client as a developer plugin and has not been submitted to mod.io yet. Everything on this page describes what is built and tested today.

Backpack, worn items, every member's bank and the shared group storage.

What's new in 2.0

A plugin for the RuneScape client

A Lua plugin built on Jagex's official plugin system reads your own character and sends it to your group's dashboard: skills, backpack, worn items, bank, group storage, position, quests, completed achievements and area tasks, the Group Ironman Journey, lifetime boss kills, kills and notable drops. See the plugin section.

One player filter for the whole dashboard, and compare

The player cards that used to live on the Overview are now pinned above every page. Click a card and every page shows only that player. Click more cards to compare just those players side by side. The separate player dropdowns in Goals, Vault and Items are gone. Click a selected card again to deselect it; with nothing selected you see everyone. See Player cards & filter.

One group secret for the website and the plugin

The secret your group gets when it claims the group unlocks the website and connects the plugin. In the game the plugin asks for it once; type it and press Connect. See Install & connect.

Live XP drops

XP gained in each skill floats up from the member's player card as it happens (about every 30 seconds while they play), and the Live XP tile shows each member's XP of the last hour and every drop of the last day. See Overview.

Boss log, clue log and clue competitions

Leaderboards now keep a boss log (every kill the game counts, with the drops linked to each boss) and a clue log (every clue a member completes, per tier). Clues completed are also a board on the group leaderboard and something to race for in competitions. See Leaderboards.

Backpack as in the game, with the money pouch

The inspect panel shows the backpack slot by slot, exactly as in the game (noted items drawn on their note), and the coins in the money pouch, shortened like the game does (white K, green M, blue B). See Player cards.

Drops, Goals and Leaderboard tiles

Three tiles beside the activity feed open as panels that float over the page: the Drops chest, your Goals, and the Leaderboard with day, week and month boards and the group's own competitions. See Overview.

Manage group

Adding a character by hand, correcting a name and removing a member moved off the player cards into one Manage group window (the + button in the top bar). See Top bar.

Group Vault, Bank Journal and the group storage

Items moved into the Group Vault: the shared group storage plus everyone's bank, with filters. The Bank Journal records only what goes in and out of the group storage. See Group Vault.

Quests and Tasks on one page

Quests, area tasks and achievements share one page with a summary, per-player progress, and the Group Ironman Journey always visible beside the lists. See Quests and Tasks.

Exact boss kills and a better Firsts board

Boss kill counts now come from the game itself and match the in-game tracker exactly. Firsts counts a boss as killed even when the 20-event Adventurer's Log feed has long forgotten it. See Leaderboards.

Cleaner top bar and real RuneScape icons

The group name, type, member count and rank sit in the top bar, Plugin setup is one click away next to Docs and Discord, and navigation uses official RuneScape icons instead of emoji. See Top bar.

How it works

RuneScape client                      Your server                            Browser
┌─────────────────────┐   HTTPS POST  ┌──────────────────────────┐  GET   ┌───────────────┐
│ GIM Companion (Lua) │ ────────────▶ │ /api/plugin/ingest       │ ◀───── │ Dashboard     │
│ reads YOUR character│  Bearer key   │  validates, stores,      │ group  │ (React + Vite)│
│ every ~30 s         │               │  de-duplicates           │ auth   └───────────────┘
└─────────────────────┘               │ SQLite database          │
                                      └──────────────────────────┘
  • The plugin only reads. It never sends actions back into the game and never touches other players.
  • One secret per group. Members type the group secret into the plugin once. The plugin trades it for a key that can only write that member's own character while the character is in the group, and keeps the key instead of the secret.
  • Sends are retry-safe. A lost response can never count a kill, a deposit or a drop twice.
  • The dashboard reads with the group secret. Bank data and live items are private to the group.

Quick start

GIM 2.0 currently runs locally. You need Node 22 or newer (it uses the built-in node:sqlite).

git clone https://github.com/thosjo95/RS3-GIM-Companion-2.0.git
cd RS3-GIM-Companion-2.0
npm install --prefix server
npm install --prefix client
npm run dev            # API on :3001, dashboard on :5173

Try it without the game

node server/scripts/devShowcase.js # "Misthalin Five": five made-up members with data in every feature
                                   # (secret SHOW-CASE-2026, dev database only; used for the screenshots)
node server/scripts/devDemo.js     # a smaller demo group with fake players and items

Connect the real plugin

  1. Open the dashboard and click Plugin in the top bar. A group nobody has claimed yet is claimed right there: that creates the group secret, which the claimer saves and shares with the group. A claimed group is unlocked with that secret.
  2. Follow Install & connect: the plugin asks for the group secret in the game.

Player cards & filter

The group's player cards sit above every page. They are the player filter:

  • Click a card: every page shows only that player. The card gets a coloured border and the header says so.
  • Click more cards to compare just those players. The Overview then shows the same Group Stats grid as for the whole group, limited to the selected players, under the heading Comparing N players.
  • Click a selected card again to deselect it. With nothing selected, every page shows everyone.
  • A green dot on a card means that member is online and playing right now (the plugin's heartbeat).
  • The magnifying glass on a card opens a floating panel with that player's backpack, worn equipment and skills: live while they play, and as last seen after logout. Hover a skill for its XP and the XP to the next level.
  • Your own card has the YOU badge. For a Group Ironman the member list follows the official hiscores; new members are added automatically every night and nobody is removed automatically.

Group Vault

Three sections:

Drops & Gear

The Drop Log (items your group has logged, now including drops the plugin detects) and Worn Gear (what the selected player is wearing, live).

Group Vault

What the group owns, live from the game:

  • Storage (default): the shared group storage plus everyone's bank.
  • Filters for Group storage, Banks, Backpacks, Equipped and Everything, plus search and sort by quantity, value or name.
  • Each item lists where it is held and how many. Values are the game's base value, not Grand Exchange prices.
  • The group storage is the same for every member, so the newest snapshot from any member's plugin is used. A member has to open it in-game once.

Bank Journal

Every deposit and withdrawal in the group storage: time, item, amount, value and member. Filter by deposits or withdrawals and search items. Members' own bank movements are deliberately not recorded.

Quests and Tasks

One page for everything the group completes.

  • Summary tiles: average quests completed, quest points, average area tasks completed, quests the whole group has done.
  • Per-player cards: quests and area tasks side by side, with a green LIVE badge when the numbers come straight from the game.
  • Quests: a grid of every quest by player, with filters (not all done, in progress, group complete), difficulty, and free-to-play vs members. Plugin data is exact; players without the plugin fall back to the Adventurer's Log.
  • Area Tasks: the region × tier grid. Completed sets are read from the game and fill the grid; you can still mark cells by hand.
  • Achievements: everything completed, who completed it, recently completed, with search and category filters.

Group Ironman Journey

The journey panel sits beside the lists and stays visible whichever section is open. It shows:

  • The group is on Tier N (the first tier someone still has to finish) and how many steps are left.
  • Each player's tier, for example tier 5 done · tier 6: 5/6.
  • All eleven tiers with a progress bar. Expand a tier for every step, its description and reward, a dot per player, and a progress counter such as total level 2,497 / 2,600.

The journey is read from each member's own character by the plugin. Members without the plugin have no data and are left out of the group figures, so they never drag the group back to tier 0.

The RuneScape plugin

GIM Companion is a Lua plugin for the official RuneScape 3 plugin system (Lua 5.4, launched with the new client). It lives in plugin/gim-companion/. Official docs: developer.runescape.com/rs.

FilePurpose
plugin.jsonThe manifest: name, contact address, permission (httpAccess) and the server URL.
main.luaThe plugin: reading the game, batching, sending.
json.luaA small JSON encoder/decoder (the game provides none).
config.luaOptional: the group secret (instead of typing it in the game) and test settings. Never share it, never commit it.
install-dev.ps1Copies the plugin into the beta client's dev_plugins folder (keeps your config.lua).

Install & connect (developer / beta)

  1. Get the beta client. Launch the RuneScape beta from the link in the official tutorial, log in, click import save in the lobby (once an hour is allowed), then relaunch. This creates C:\ProgramData\Jagex\RuneScape-BETA.
  2. Start the dashboard (npm run dev) and unlock your group.
  3. Install: powershell -File plugin\install-dev.ps1 (the copy points at the dashboard on your own computer).
  4. Open the console in the beta client: Alt + the key under Esc. The console's first lines name the keys on your layout (for example Alt-§, Alt-² or Alt-ø on a Nordic keyboard). Then enable the plugin: 
    prf                                   # refresh the plugin list
ppr gim-companion                     # the plugin asks for its permission
ppe gim-companion httpAccess          # allow network access
pon gim-companion                     # enable it

Connect with the group secret

Log in with the plugin enabled. A small GIM Companion window asks for your group's secret, the one that unlocks the website (members see it under Plugin in the top bar). Type it and press Connect or Enter. The plugin sends it once to /api/plugin/join with the character name. If that character is a member of the group with that secret, the server returns a key for that character only; the plugin keeps the key (per character, on that computer) and forgets the secret. The box shows what you type, because the game gives a plugin no text from a masked box. Prefer a file? Put groupSecret = "XXXX-XXXX-XXXX" in config.lua and no window is shown.

The plugin prints [GIM] lines. A healthy start looks like httpAccess granted: true and, once connected, ... joined <group>. Sending to the dashboard. Open the group's Plugin window to see the green dot and "last update".

Privacy & safety

The full privacy notice explains what is collected, why, where it is stored, how long it is kept and how to have it deleted.

  • Own character only. Every update names the character; the server refuses it (HTTP 409) if the key belongs to someone else, so a key can't store another character's data when you log into an alt. An alt that is not in the group cannot join at all.
  • Read-only. The plugin never sends clicks, chat or actions into the game, and never reads chat. It asks for one permission: httpAccess.
  • Nothing about other players. No friends list, no nearby players' names or data. Kill/drop logic looks at monsters and item drops, never at other players.
  • One secret, per-character keys. The group secret is sent once to join and not kept by the plugin. The key it gets back is stored hashed (SHA-256) on the server and can be disconnected per member. Wrong secrets are rate limited (10 attempts a minute).
  • Where data goes. Only to the address in plugin.json (urls). Group data is readable only with the group secret.
  • No clock, no files. The game's Lua has no os library and plugins cannot write files, so the plugin cannot do either.

A full privacy notice for the mod.io listing (what is collected, retention, deletion, contact) is still to be written; see Submitting to mod.io.

Lessons from the game API

Things that are not obvious from the documentation, found by testing in the beta client:

GotchaWhat to do
There is no global logUse print; output appears in the console with a >> prefix.
There is no os libraryNo clock, no timestamps: let the server stamp events.
pcall(HTTPRequest.new, …) crashes the clientCreate requests from inside a Lua function: pcall(function() return HTTPRequest.new(base, path) end). The game seems to identify the calling plugin from the Lua caller.
Post/Get second callback is progressPass only the completion callback; it fires on success and on failure.
prf resets permissionsRun ppe <plugin> httpAccess again, then prl.
HasPermission must be checkedWithout it, network calls raise an error instead of running.
Plain http://localhost worksFor development. Production must use https.
invalid ValueType (16) in the consoleThe game refuses to convert one kind of config value. Wrap reads in pcall; it is harmless.
Heavy scans freeze the client if done at onceSpread scans over ticks (the plugin reads 25–200 ids per tick).
Names with spaces in the RSNRuneScape treats spaces, underscores and non-breaking spaces alike; the server compares them normalised.
Window must be open to read bank / storageInventories of closed windows are unreliable, so the plugin never treats "empty" as "withdrawn".

Useful API facts

  • Skills: SkillType.HITPOINTS (not Constitution), SkillType.RUNECRAFTING.
  • Inventories: Inventory.Find(id.Inv.INV | WORN | BANK | GROUP_IRONMAN_STORAGE_CLAN_TEMP), windows: ui.Interfaces:GetInterface(id.Interface.BANK).
  • Position: x = mapSquareX*64 + localX, y = mapSquareZ*64 + localZ, plane = level.
  • Definitions: config.Quest, config.Achievement, config.Struct, config.Param, config.Enum, config.DBTable, config.Obj.FromID(id).name / .cost.
  • Events used: ServerLogic (about 0.6 s), InventoryUpdated/Added/Removed, SkillTransmit, NPCEntityRemoved, ObjStackEntityAdded, GameStateChanged.

Kill tracker discovery

How the exact boss kill counts were found, because the same approach finds more:

  1. The hiscores and Adventurer's Log APIs have no lifetime boss or Slayer kills (only 20 recent, batched events).
  2. The game stores kill counts in player variables bslay_boss_killsN / bslay_monster_killsN (each holds two 16-bit counters), but not all of them.
  3. The in-game tracker is built from records ("structs") named BSLAY_…: 58 bosses, each with BSLAY_NAME, BSLAY_ID, an NPC, drops, tactics and a BSLAY_ACHIEVEMENT whose progress counter is the lifetime kill count.
  4. Verified against the tracker screen: Barrows 142, K'ril Tsutsaroth 1,062, Queen Black Dragon 22, Hermod 68 … all match.

Slayer creatures are structs with SLAYER_NAME and SLAYER_TYPE but no counter link; their counts live in the packed variables and are being mapped (see Roadmap).

The developer probes (trackerProbe in config.lua) are:

ValuePrints / saves
trueData tables with relevant-sounding names.
"structs"Enums and structs that mention bslay.
"bosses"Every boss record (name, id, flags) saved for analysis.
"params"All parameters of a few boss records.
"tallies"Each boss with its achievement counter.
"slayer", "creatures"Slayer structs and the creature record dump.

Troubleshooting

"Waiting for network access (httpAccess)"

Run ppr gim-companion (the plugin asks for its permission), then ppe gim-companion httpAccess (you grant it), then prl gim-companion. Remember prf resets it. The plugin prints httpAccess granted: true at start when it is right. It also starts by itself as soon as the permission is allowed later (Network access allowed. GIM Companion is starting.), so a reload is not needed.

"No claimed group with ... as a member has that secret"

Check the secret (letters and digits; dashes and lower case do not matter), that the group is claimed, and that this character is a member on the website. A character added to the group later can connect as soon as it appears in the member list.

"the server no longer accepts this character's key"

Someone pressed Disconnect for this member, or the member was removed. The window asks for the secret again.

The game closes when the plugin starts

Create requests with the wrapped form (see Lessons). If it still happens, set dryRun = true to see whether reading is safe, then probe = "local" for the network, and report the last [GIM] > line (or read gim_last_step from PluginData.db).

Nothing appears on the dashboard

  • Is the dev server running and the URL in plugin.json right?
  • Open Plugin: a green dot means data arrived in the last 10 minutes.
  • Open the bank or the group storage window once, and give the first scan a minute or two after login (quests and achievements are scanned in small steps).

I can't open the console

The key is "under Esc" on your layout, not always `. The console's banner lists the working keys (Alt plus §, ² or ø on Nordic keyboards, ` on US/UK).

The ingest payload

Every section is optional and independently validated; a bad section rejects the request with a message the plugin author can act on.

{ "v": 1, "rsn": "Your Name",
  "position": {"x":3200,"y":3200,"z":0},
  "skills": {"Attack":{"xp":1000,"level":10}, ...},
  "inventory": [...], "equipment": [...], "bank": [...], "group_storage": [...],
  "storage_changes": [...], "changes_ref": "…",      // Bank Journal, retry-safe
  "quests": [...], "quests_full": true,              // baseline once per login
  "achievements": [...], "achievements_full": true,
  "boss_kills": [{"key":"BSLAY_BARROWS","name":"The Barrows Brothers","kills":142}],
  "kills": [...], "kills_ref": "…",                  // live kill batches, retry-safe
  "drops": [...],                                    // each with a unique ref
  "kill_vars": {"bslay_boss_kills2": 9306115} }

Security

  • One group secret for people; the plugin trades it once for a per-player key, stored hashed, that can only write that player's data.
  • Joining is rate limited and answers the same way whether the name or the secret was wrong.
  • The character name is checked on every update.
  • Strict validation and limits on every section; unknown fields ignored.
  • Rate limiting on ingest.
  • Idempotent writes: references for kill batches, ledger batches and drops mean a retried request never duplicates data.
  • Group data is private: reads need the group secret. The group is derived from the record, never from a client-supplied header.
  • Authentication, rate limits and password handling for the 1.x features are unchanged.

Testing

npm test --prefix server     # API: auth, validation, isolation, limits
npm test --prefix plugin     # runs the real main.lua against a MOCKED game API and feeds the output to the real server
npm run build --prefix client

The plugin test uses fengari (Lua in JavaScript) with a mock of the game API shaped like the real one (no os, callbacks, permissions, events). It proves the logic and the wire format, including retries, lost responses and wrong-character rejection. It cannot prove the real game's names, which is what the beta client is for.

Roadmap & limits

Known limits

  • Boss hard / enrage modes have no separate record and are not read.
  • The boss list is fixed in the plugin (58 bosses); a new boss needs one more entry.
  • Slayer creature kills are not mapped yet.
  • Item values are the game's base value, not Grand Exchange prices.
  • Members without the plugin only have the 1.x data.

Next

  • Slayer creature kills (name ↔ packed counter mapping).
  • A live map from the position data (opt-in), HP/prayer, XP history graphs.
  • Submission to mod.io.
